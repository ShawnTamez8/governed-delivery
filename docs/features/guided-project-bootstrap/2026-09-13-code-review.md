## Summary

The implementation preserves external-only signing, one CLI mutation authority,
the frozen-profile core, and the no-retry boundary. Four reachable continuation
defects remain: intake can race into duplicate exact identities, an expired
handoff cannot rotate, generated bytes reject a clean CRLF checkout, and
terminal reruns omit actionable failure evidence.

The review withheld deliberate external-only signing custody, low-level
unbound-signer compatibility, fixture adaptations, and the documented
interactive-test composition. It also withheld style, speculative hardening,
the reconciled plan findings, the non-reproduced Windows cleanup race, and work
beyond the authorized increment.

## Findings

### Finding 1 — Concurrent guided intake creates duplicate exact-tuple runs

- **Where:** `src/guided-command.ts` (`runGuidedCommand`, intake branch).
- **Severity:** High. Two ordinary guided processes can create duplicate
  nonterminal runs, making later selection ambiguous and risking duplicate paid
  work.
- **Reproduced:** Two no-provider invocations were synchronized at the model
  prompt. Both declined paid execution and returned normally, while the store
  contained two `in_progress` runs with the same project, feature ID, slug, and
  change kind. The pre-prompt snapshot was not rechecked after acquiring the
  writer lock, and the schema has no matching uniqueness constraint.

### Finding 2 — An expired guided approval payload permanently strands the run

- **Where:** `src/guided-command.ts` (`ensureApprovalHandoff`).
- **Severity:** High. A normal delay past the retained payload expiry leaves no
  supported guided route to approval or a fresh payload.
- **Reproduced:** A canonical payload with a past expiry was retained at the
  documented handoff path. Repeated guided invocations returned the same
  expired bytes; adding its valid signature could only reach the deterministic
  `approval expired` refusal because replacement payload bytes were rejected.

### Finding 3 — A clean `core.autocrlf=true` checkout is rejected as a changed starter

- **Where:** `src/project-bootstrap.ts` (`classifyExistingProject`).
- **Severity:** Medium. The implemented Windows installation can reject its own
  clean generated starter after a normal clone.
- **Reproduced:** A generated starter cloned with
  `git -c core.autocrlf=true clone` had empty porcelain status but guided
  preparation refused `.gitignore` because LF constants were compared with
  CRLF working-tree text byte for byte.

### Finding 4 — Terminal handoff omits the block reason and final finding evidence

- **Where:** `src/operator-output.ts` (`formatGuidedTerminal`) and its terminal
  callers in `src/guided-command.ts`.
- **Severity:** Medium. An operator rerunning a blocked or failed exact run sees
  only a finding count, without the durable reason, attributable findings, or
  the read-only inspection command required by GBP-AC-13.
- **Reproduced:** A blocked snapshot with a blocking finding and `policy_block`
  reason rendered `Final findings: 1` but neither the finding nor the reason.
  All terminal rerun call sites return only this formatter.

## Reconciliation

**Date:** 2026-09-13
**Disposition:** 8 accepted, 0 rejected, 0 deferred, 0 open
**Status:** reconciled
**Hazards considered:** 4 required failing regressions before each accepted correction; 6 required expired authorization evidence to rotate without stranding continuation; 8 required Git-native clean-tree comparison across Windows line-ending conversion; 11 required the default guided path to remain usable after races and expiry; and 12 required run identity and terminal evidence to agree across every entrypoint. Other hazards remained governed by unchanged stage, parser, review, and delivery code.

### Original findings

- **Accepted — Concurrent guided intake creates duplicate exact-tuple runs.**
  Intake now re-queries project, feature ID, slug, and change kind while holding
  the repository writer lock and repeats the complete nonterminal/terminal
  cardinality decision before insertion. A synchronized two-process regression
  creates one run.
- **Accepted — An expired guided approval payload permanently strands the
  run.** A canonical expired handoff is atomically moved as one directory,
  validated from the moved payload against the frozen binding, preserved as
  inert expired evidence, and replaced with a freshly and exclusively created
  canonical payload. Any signature bytes move with expired evidence but are
  never treated as valid authority or submitted.
- **Accepted — A clean `core.autocrlf=true` checkout is rejected as a changed
  starter.** Committed generated blobs remain compared with exact LF source
  constants, while the worktree is compared with HEAD through Git. A clean
  CRLF clone now resumes and substantive edits still refuse.
- **Accepted — Terminal handoff omits the block reason and final finding
  evidence.** Guided terminal output now includes every workflow refusal,
  final-panel finding ID/location/blocking state, reviewer attribution,
  severity, subject, code-review evidence references, and an exact read-only
  `buildworks status` command.

### Follow-up findings

- **Accepted — Malformed retained expiry was presented for signing.** Retained
  expiries now pass the existing exact ISO, real-date, expiry, and maximum
  lifetime validator before any binding is rendered. Malformed and over-limit
  values refuse without external-signing instructions.
- **Accepted — Final finding output omitted reviewer attribution.** Each final
  report now names its retained reviewer ID or explicitly states that
  attribution is unavailable. The complete fixture journey retains a
  nonblocking low finding and proves the reviewer appears in terminal output.
- **Accepted — Per-file archival left a validation-to-rename race.** Rotation
  now renames the complete handoff directory to a provisional path atomically,
  validates the exact moved payload, and only then promotes that directory to
  its deterministic expired archive. A failed validation restores the
  provisional directory when safe and never labels it archived.
- **Accepted — Requiring an expired signature to validate recreated the
  renewal dead-end.** Signature bytes beside an already expired, canonical
  payload are preserved as inert evidence rather than used as a prerequisite
  for renewal. This separates evidence retention from approval authority and
  lets malformed or partial stale signatures rotate without ever entering
  `approveRun`.
