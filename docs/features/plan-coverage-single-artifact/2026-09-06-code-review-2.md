## Summary

Do not start the paid run yet. The implementation aligns the three authoring prompts, the reviewer prompt, the gate message, and the recorded response, and it keeps the refusal verdict closed. The concurrent independent pass also corrects two issues present at the start of this review: it replaces the false “one-to-one” description with one line per criterion and tells reviewers that several criteria may name the same artifact; it also preserves the legal `not_applicable` form. The second issue remains plausible until a live panel sees the revised prompt, but its trigger already exists in the recorded AC-017 case.

## Findings

**Finding 1 — Separator detection reports a legal single path as a list**

- **Where:** `src/plan-gate.ts:93` in `coverageFitsScope`, plus the list-specific assertions in `test/plan-gate.test.ts` and `test/reconciliation.test.ts`.
- **Why it matters:** `validateSpecDoc` permits commas, semicolons, and vertical bars in declared artifact paths because its membership rule rejects whitespace only. A specification can therefore sign `src/original,file.ts`. If a plan names the single but out-of-scope path `src/renamed,file.ts`, the gate correctly blocks but falsely says “a list of paths is not a path.” The operator can repair the wrong property, start a fresh paid run, and meet the same scope refusal again. This conflicts with the proposal review's requirement to explain exact scope membership without guessing from model punctuation and engages hazards 3 and 7.
- **Reproduced:** A temporary review test first validates a specification declaring `src/original,file.ts`, then calls `coverageFitsScope` with `src/renamed,file.ts`. The gate returns `plan.coverage.unkeepable` with the list-specific clause. The test fails on that clause and is removed after capture.
- **Required correction:** Remove punctuation-based intent inference. For every mismatch, state that the received target must equal exactly one signed-scope path and include the received value. Keep `unkeepable` as the typed criterion-ID signal. If punctuation itself becomes illegal, make that a separate schema decision and enforce it where the specification declares the path.
- **Reconciled (2026-09-06):** accepted as written. The separator predicate is gone from `coverageFitsScope`; every mismatch now reports `<criterion> -> <received target>` followed by the same unconditional sentence, "an artifact-form coverage entry names exactly one path copied from the signed scope", and `unkeepable` still carries only criterion IDs. `test/plan-gate.test.ts` ("the refusal names the target that failed and the membership rule, without inferring intent") pins the plain out-of-scope case and the recorded `AC-008` pair to byte-identical text, so no list-specific clause can return. Punctuation in a path stays legal; no schema decision was taken. Recorded as deviation 1 in the plan's implementation note.

**Finding 2 — Multi-file criteria still have no defined representative anchor**

- **Where:** `ARCHITECTURE.md:303`, `src/prompts.ts:309`, `src/prompts.ts:393`, `src/prompts.ts:469`, and `src/prompts.ts:765`.
- **Why it matters:** The recorded AC-017 obligation requires both the control in `src/index.html` and behavior in `src/theme.js`; neither file alone “carries the obligation.” The author must nevertheless choose one, while the reviewer prompt still treats “coverage line naming the wrong artifact” as a valid finding. Different models can therefore select different equally necessary files and disagree about which is wrong, recreating an unanswerable finding at the paid boundary. The proposal review requires the path to mean a representative delivery anchor, not an exhaustive implementation list, but the implementation never adopts that meaning or a selection rule. This engages hazards 3 and 16.
- **Not reproduced:** No post-change provider run exists, and a deterministic test cannot establish which semantic anchor a model chooses. The current prompt text and the recorded multi-file criterion establish reachability, not frequency.
- **Required correction:** Define the artifact as the representative signed-scope path most directly responsible for the criterion's observable outcome. State that it is non-exhaustive. Let reviewers report an anchor unrelated to the criterion, but forbid a finding based only on another contributing file being absent from Coverage.
- **Reconciled (2026-09-06):** accepted as written; the text half is done and the live half is not. `ARCHITECTURE.md` section 8 and all four plan prompts (`buildPlanAuthorPrompt`, `buildPlanSelfCritiquePrompt`, `buildPlanReconcilePrompt`, `buildPlanReviewPrompt`) now define the path as the criterion's representative delivery anchor, not an exhaustive list, with the selection rule "the declared artifact most directly responsible for the criterion's observable outcome". The review prompt keeps "a coverage line naming the wrong artifact" as a finding and states that "this criterion also touches another file" is not one, redirecting it to the plan's tasks. `test/prompts.test.ts` pins the phrase in each builder. What remains unverified is exactly what the finding said a deterministic test cannot establish: whether a live author and panel converge on one anchor for `AC-017`. That is Task 7, which has not reached the plan stage (`real-run-evidence.md`). Recorded as deviation 2 in the plan's implementation note.
